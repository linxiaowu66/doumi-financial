# 投资管理系统改造说明（新手版）

这份文档解释本次系统改造做了什么、为什么做、页面上的数字怎么算，以及目前哪些地方不能被误解成“预测收益”。文中的金额、日期和基金名称均为脱敏后的虚构示例，不代表当前账户真实数据；实际情况请以系统页面为准。

## 一、先说结论

这次改造的目标不是让系统保证赚钱，而是让它做到四件事：

1. 只显示当前用户自己的数据，避免不同账户串数据。
2. 把“赚了多少钱”和“承担了多大风险”分开看。
3. 把基金的官方分类、公开资产配置和披露持仓保存下来，和你的个人分类并列展示。
4. 根据已有净值和仓位，给出“买入观察 / 暂缓加仓 / 持有”等研究信号。

系统给出的都是辅助判断，不是自动交易指令，也不代表收益承诺。

## 二、数据安全和历史数据

### 1. 用户隔离

以前部分接口只按基金 ID 或投资方向 ID 查询。现在接口会先确认当前登录用户，再查询数据。

例如：

```text
用户 A 请求基金 27 → 只有当基金 27 属于用户 A 时才返回
用户 B 请求基金 27 → 返回“基金不存在”或无权访问
```

这不是删除数据，而是避免把别人的数据返回给当前用户。

### 2. 历史 AI 报告恢复

历史 AI 策略报告会按当前登录用户隔离保存。旧数据如果缺少用户归属，需要先经过人工确认和一次性迁移，不能把未知归属的报告直接展示给所有用户。

## 三、年度目标驾驶舱

首页现在会显示：

- 年度目标，例如 100,000 元；
- 当前已实现收益；
- 目标缺口；
- 距离年底剩余天数；
- 如果只靠当前市值，需要达到的数学收益率。

### 示例

假设：

```text
年度目标：100,000 元
今年已实现：12,000 元
目标缺口：88,000 元
当前市值：400,000 元
剩余 90 天
```

系统计算的“按当前市值所需收益率”大约是：

```text
目标缺口 ÷ 当前市值
= 88,000 ÷ 400,000
≈ 22%
```

这只是数学题，不是预测。它不能说明市场一定会涨 26.51%，也不能说明应该加杠杆或集中押注。

## 四、收益归因：钱是怎么赚或亏的

投资方向详情页现在会把收益拆成：

- 当前持仓收益：还持有的基金目前赚/亏多少；
- 已实现收益：已经卖掉的基金赚/亏多少；
- 现金分红；
- 红利再投资；
- 手续费；
- 组合总收益。

### 简化示例

```text
当前持仓收益：-5,000 元
卖出收益：+1,000 元
现金分红：+200 元
再投资分红：+100 元

组合累计收益
= -8,000 + 1,500 + 300 + 100
= -3,700 元
```

这样可以避免只看“当前持仓亏损”，却忽略之前卖出已经赚到的钱。

## 五、风险分析：不再只罗列收益

收益归因区域现在增加了以下指标。

### 1. 最大回撤

最大回撤表示：从历史高点跌到之后低点，最严重跌了多少。

```text
历史高点：100 元
之后最低：80 元
回撤 = (80 - 100) ÷ 100
= -20%
```

页面显示绝对值 20%，表示历史上曾经从高点回落约 20%。

系统会尽量扣除期间新增投入，避免把“后来加钱”误认为收益增长。

### 2. 年化波动率

波动率表示每天涨跌幅有多大。波动越高，净值曲线越不平稳。

系统先计算每天收益率的标准差，再按一年约 252 个交易日年化：

```text
年化波动率 ≈ 每日收益率标准差 × √252
```

波动率高不等于一定亏损，但表示持有过程可能更颠簸。

### 3. 夏普比率

夏普比率可以粗略理解为“承担一份波动，换来了多少收益”。

```text
夏普比率 ≈ 年化收益 ÷ 年化波动率
```

通常：

- 越高越好；
- 接近 0，说明收益不足以明显补偿波动；
- 为负，说明承担波动后仍然亏损。

数据太少时，系统不强行计算，会显示数据不足。

### 4. 回撤修复时间

如果净值从 100 跌到 80，后来又回到 100，用了 60 天，那么回撤修复时间就是 60 天。

如果目前还没有回到历史高点，系统不会假装已经修复。

### 5. 组合集中度 HHI

HHI 用来观察是否过度集中在少数基金上。计算方式是把每只基金权重平方后相加：

```text
基金 A：70%
基金 B：30%

HHI = 70² + 30²
     = 5,800
```

为了方便页面阅读，系统显示换算后的百分比形式。权重越集中，HHI 越高。

## 六、持仓结构饼图

收益归因区域的持仓结构已经改为环形饼图：

- 每一块代表一只当前有市值的基金；
- 面积代表该基金占投资方向当前市值的比例；
- 已清仓或 0% 的基金不会挤占图表空间；
- 鼠标悬停可以查看具体权重；
- 下方表格仍保留收益、分红、费用等明细。

### 示例

```text
黄金基金：37.7%
红利基金：13.4%
科技基金：10.1%
其他基金：38.8%
```

这能快速看出：某类资产是不是占比过高，而不仅仅是看单只基金赚了多少。

## 七、基金官方资料和个人分类

系统现在把两类概念分开：

### 个人分类

这是你自己设置的分类，例如：

```text
成长高风险、固收、黄金、红利
```

它适合做自己的投资计划和目标金额。

### 官方分类

这是从公开基金详情资料同步的分类，例如：

```text
指数型-海外股票
债券型-混合一级
混合型-偏股
QDII-普通股票
```

两者不会互相覆盖，页面会用“个人分类 / 官方分类”并列显示。

## 八、分类目标仓位怎么计算

现在只需要设置“目标仓位”，不再配置最低仓位和最高仓位。

目标仓位不是当前市值的比例，也不是历史平均值，而是这类资产计划使用的预期投入比例。

### 示例

假设一个投资方向的预期投入是 100,000 元：

```text
成长高风险：40% → 100,000 × 40% = 40,000 元
黄金：30%       → 100,000 × 30% = 30,000 元
红利：20%       → 100,000 × 20% = 20,000 元
固收：10%       → 100,000 × 10% = 10,000 元
```

四类目标仓位合计 100%，目标金额合计就是 100,000 元。

系统会用该分类的已投入金额和目标金额比较：

- 低于目标金额：说明还没有达到计划投入，可以继续观察是否需要买入；
- 达到目标金额：提示该分类已达到目标，不再建议继续加仓；
- 超过目标金额：标记为超出目标，但不会自动卖出。

当前市值仍然会展示，用来观察盈亏和当前组合结构，但不会改变目标金额。例如基金上涨后市值变成 45,000 元，不代表原本 40,000 元的目标金额自动变成 45,000 元。

目标仓位合计最好设置为 100%。系统只提供提醒和研究信号，不会自动买入、卖出或强制再平衡。

## 九、基金详情页的 metadataJson

基金详情页新增“基金官方资料”区域，系统会把数据库中的 `metadataJson` 解析展示为：

- 官方分类；
- 披露日期；
- 最近同步时间；
- 股票、债券、现金等资产配置；
- 前十大底层资产及披露占比；
- 数据来源和时效说明。

`metadataJson` 是一个资料快照，不是实时行情。例如：

```json
{
  "assetAllocation": {
    "股票占净比": 0,
    "债券占净比": 0.24,
    "现金占净比": 5.09
  },
  "holdings": [
    { "name": "25国债13", "weight": 0.24 }
  ]
}
```

部分基金没有公开完整持仓，页面会显示“暂无前十大持仓披露数据”，不能把缺失数据当成 0%。

## 十、P0 基金研究信号

首页的“今日基金信号”现在按基金策略类型使用不同规则：

- 长期核心资产：主要给出持有、暂缓加仓和目标仓位相关提示；
- 高风险趋势资产：额外检查 20 日/60 日均线、回撤和波动率，可给出减仓观察或分批卖出提示。

基金编辑窗口中的“投资策略类型”可以选择“长期核心资产”或“高风险趋势资产”。这是策略标签，不等同于基金的官方资产类型。为了兼容旧数据，个人分类名称包含“高风险 / 创业 / 科创”时，目前也会辅助识别为趋势资产；如果想明确控制规则，建议直接设置“高风险趋势资产”。

信号只使用最近一个完整交易日（T-1）及以前的净值，不使用盘中估算值。数据不足或数据过旧时，系统会明确提示，避免强行给出买卖结论。

信号综合使用：

- 最近净值；
- 20 日和 60 日均线；
- 近 5 日、20 日、60 日收益；
- 当前回撤和历史最大回撤；
- 20 日年化波动率；
- 已投入金额占投资方向预期投入的比例；
- 基金策略类型和数据新鲜度。
- 分类目标仓位（如果已设置）。

基金的“权益 / 固收 / 黄金”等资产类型，优先使用官方分类和已保存的 `metadataJson`（例如最新股票占比、债券占比），个人分类只用于组合分组、目标仓位，以及官方资料不足时的兜底。也就是说，“成长高风险”是你的投资计划标签，不会覆盖基金官方的真实分类。

### 示例

```text
高风险趋势基金连续跌破 20 日均线
20 日均线低于 60 日均线
当前仍有持仓
→ 分批卖出
```

另一个例子：

```text
最新净值高于 20 日和 60 日均线
近 20 个净值点收益为正
当前已投入比例低于目标仓位
→ 分批买入
```

“分批卖出”也不是自动交易指令，而是高风险趋势资产的风险退出提醒。核心资产不会因为短期跌破均线就自动触发卖出。你仍然需要结合基金资料、市场环境、确认天数、费用和自己的现金流决定是否操作。

系统不会把“跌得越多就越应该买”直接当成买入理由。当前允许一种回撤恢复场景：先要求回撤达到一定程度，再等待短期动能止跌并重新站回 20 日均线，同时仍要满足分类预算没有用完，并限制单次补仓金额。它和趋势向上时的补仓一样，都是分批候选，不是猜最低点。

### 10.1 把策略想成一套“检查清单”

系统不是预测明天涨跌，而是按固定顺序检查几个问题：

1. **数据是否可靠**：只用最近一个完整交易日（T-1）及以前的正式净值，避免把盘中估值当成收盘事实。
2. **趋势是否向上**：20 日均线代表最近一个月左右的平均价格，60 日均线代表更长一段时间的平均价格。净值在两条均线之上，说明短中期趋势较强。
3. **动能是否支持**：同时看近 5 日、20 日、60 日收益，避免只因为某一天上涨就给出买入提示。
4. **风险是否变坏**：看当前回撤、历史最大回撤和 20 日年化波动率。趋势资产连续跌破 20 日均线，并且 20 日均线低于 60 日均线时，才会提高卖出等级。
5. **仓位是否还有空间**：先把同一投资方向内、同一分类下的基金投入金额加总，再和“预期投入 × 分类目标比例”比较。

例如：

```text
投资方向预期投入：100,000 元
成长高风险目标：40%
分类目标金额：100,000 × 40% = 40,000 元
该分类下 3 只基金合计已投入：38,000 元
```

这时系统判断的是“这个分类还差 2,000 元”，而不是分别给 3 只基金各算一遍 40,000 元。买入信号只是候选，不会自动把 3 只基金都买到目标金额。

### 10.2 为什么只显示买入和卖出

“暂缓加仓”和“持有”是研究状态，不是你每天必须执行的动作。现在首页和“策略与风险”页面的行动列表只展示：

- **分批买入**：趋势或回撤恢复条件满足，且分类合计仓位仍低于目标；同时显示本次建议金额；
- **分批卖出**：趋势资产出现确认性的趋势破坏，且当前确实还有持仓。

“暂缓加仓、持有、数据不足”等状态仍保存在后台，用于风险统计和历史复盘，但不再占用每日决策列表。

## 十一、组合级风险和每日信号记录

“策略与风险”页面现在把今日买入 / 卖出信号、组合风险和账户管理提醒收口展示。投资方向列表页不再重复显示“资产预警概要”卡片，避免和这个页面重复。已经清仓、当前持仓市值接近 0 的投资方向不会进入组合风险卡片；它们的历史基金和买入候选数据仍会保留。

- 基金集中度 HHI：观察市值是否过度集中在少数基金；
- 分类集中度 HHI：观察股票、黄金、固收等分类是否过度集中；
- 基金平均相关性：观察多只基金是否可能同涨同跌；
- 预算使用率：已投入金额 ÷ 投资方向预期投入；
- 数据质量：净值是否新鲜、基金资料是否超过 180 天未更新、个人分类和官方分类是否存在资产类型冲突。

### 11.1 压力测试到底是什么

压力测试不是预测，也不是“系统认为一定会亏这么多”。它只是把当前仍持有的资产拿出来做几个假设：

```text
权益类当前市值 × 20%
黄金类当前市值 × 10%
固收类当前市值 × 5%
```

例如当前持有 50,000 元权益基金，假设权益资产下跌 20%，情景影响约为：

```text
50,000 × 20% = 10,000 元
```

这三个数字是三个独立情景，不能直接理解为一定会同时发生，也没有模拟汇率、基金折溢价、流动性和资产之间的联动。系统现在优先使用基金官方分类和 `metadataJson` 中的资产配置；官方资料无法细分时，才用个人分类作为兜底。

### 11.2 “分类需复核”是什么意思

它不是说基金买错了，而是指：你的个人分类推断出的资产类型，和官方资料明确披露的类型存在冲突。

例如：

```text
个人分类：固收
官方分类：指数型-股票
```

这种情况值得你确认是否误填分类。若只是“成长高风险”和“指数型-股票”这种不同命名但资产类型一致的情况，系统不会再当成异常。

官方资料本身也可能不完整。例如黄金基金有时只披露为“指数型-其他”，这时系统会注明资料粒度不足，并参考个人分类，不把缺失数据当成确定事实。

### 11.3 资产预警还保留什么

资产预警不再作为投资方向列表页的独立板块，但底层提醒仍保留在“策略与风险”页面，主要处理策略信号之外的管理事项：

- 待确认交易；
- 止盈或价格阈值提醒；
- 分类投入超过目标；
- 分类长期没有买入记录。

这些提醒回答的是“账户有没有漏处理的事项”，不是“今天应该买哪只基金”，所以和每日买卖信号分开理解。

### 11.4 家庭资产总览和月度配比

家庭资产页面现在可以把手动维护的资产账户、投资方向月度快照放在同一张配置图里，按以下大类展示：

- 股票 / 权益；
- 债券 / 固收；
- 黄金；
- 现金流 / 养老金；
- 待细分账户。

当前饼图使用官方基金分类和 `metadataJson` 识别投资方向，余额宝和个人养老金归入现金流 / 养老金，无法从账户名称知道底层资产的且慢、华泰或其他账户会单列为“待细分账户”。页面还会显示每月配比变化。

这里有两个重要限制：

1. 历史投资方向快照会按当前基金分类比例回溯，因此历史月份的细分类别是近似值；若要完全准确，需要保存每个月的基金资产分类快照。
2. 如果手动维护的且慢 / 华泰账户余额已经包含投资方向里的基金市值，同时又录入了投资方向快照，可能重复计算。建议同一笔资产只录入一处，或者把账户余额留作未细分账户并在备注中说明。

系统定时任务会按交易日保存每日信号快照，之后可以复盘“当时的信号是什么、后来发生了什么”，而不是只看今天重新计算的结果。

同时提供一个基础回测接口，用历史净值粗略比较趋势规则和买入并持有的结果。回测不包含完整的分红、滑点、限购、赎回到账延迟和真实成交价，因此只能用于筛选规则，不能证明未来一定有效。

## 十二、AI 报告的限制

AI 报告现在被明确要求：对于系统没有的数据，必须写“数据不足”，不能编造，包括：

- 历史最高净值和真实最大回撤；
- 波动率、夏普比率、回撤修复时间；
- 基金具体业绩基准；
- 债券久期、信用评级和杠杆；
- 海外基金汇率贡献；
- 账户现金比例和全部家庭资产仓位；
- 预警价格的准确形成时间；
- 基金之间的相关性和组合压力测试。

这意味着 AI 报告里的“数据不足”是保护措施，不是系统故障。

## 十三、数据的时间和准确性边界

需要特别记住：

1. 基金净值通常是收盘后确认，不能等同于盘中实时价格。
2. QDII 基金受海外市场时差和汇率影响。
3. 基金底层持仓通常按季度或定期披露，不是实时持仓。
4. 公开资料接口可能暂时没有某些基金的类型或持仓。
5. 买卖信号只使用系统已保存的数据，不能替代交易平台最终确认。

## 十四、如何正确使用这个系统

建议每天按这个顺序看：

1. 先看年度目标缺口，不要因为缺口大就立即追高。
2. 看持仓饼图，确认有没有某只基金或某类资产过度集中。
3. 看最大回撤和波动率，判断自己能不能承受这类波动。
4. 查看基金官方分类和披露持仓，确认它是否真的符合你的计划。
5. 再看今日基金信号，把信号当作候选清单，不要当作自动指令。
6. 最后结合现金流、费用、确认日和自己的风险承受能力决定是否操作。

## 十五、当前没有做的事情

为了避免过度承诺，当前系统还没有：

- 自动买入或卖出；
- 盘中实时底层持仓；
- 保证收益的预测模型；
- 完整的基金相关性矩阵；
- 基于全家庭资产的压力测试；
- 自动判断某个信号一定正确。

这些功能如果以后增加，也应该先经过历史回测和风险校验，再考虑用于实际投资决策。

## 十六、最新的“发车信号”策略

现在的每日信号不再只是告诉你“趋势好不好”，而是尽量回答三个问题：

```text
今天要不要操作？
为什么现在操作？
这次最多操作多少钱？
```

### 16.1 核心资产：用目标缺口慢慢补

核心资产适合长期持有，系统不会因为一天下跌就让你卖出。它先看这个分类距离目标金额还差多少，再看净值数据是否完整、趋势是否已经明显破坏。

例如：

```text
投资方向预期投入：100,000 元
某分类目标：30% → 目标金额 30,000 元
该分类已投入：18,000 元
目标缺口：12,000 元
```

如果 T-1 数据显示短期和中期趋势没有明显破坏，系统最多建议买入：

```text
12,000 × 25% = 3,000 元
```

下一次不会因为“还差 9,000 元”就一次性补完，而是等待下一次有效信号继续分批。金额按百元取整，并且不能超过这个投资方向尚未使用的预算。

### 16.2 高风险资产：先确认破坏，再分批退出

被标记为高风险趋势的基金（例如创业、科创或手动设为趋势策略的基金）使用更严格的退出条件：

```text
连续两个已确认净值点低于 20 日均线
并且 20 日均线低于 60 日均线
```

满足后，系统按当前市值的 25% 给出“分批卖出”金额。比如当前市值 20,000 元，第一次建议卖出约 5,000 元。这样可以先降低风险，同时保留一部分仓位，避免因为一次判断错误而全部离场。

### 16.3 下跌后也可以补仓，但要等恢复确认

系统不会把“跌得多”直接当成买入理由。只有在历史回撤达到约 12% 后重新站上 20 日均线，且近 5 个交易日转强，同时分类仍有目标缺口，才会给出分批补仓信号。

这条规则的含义是：先承认市场已经便宜很多，再等待下跌暂时停止，减少接住持续下落趋势的风险。它仍然可能判断错误，所以仍按四分之一缺口分批执行。

### 16.4 家庭资产如何参与

投资方向里的基金可以计算到单只基金和分类金额。手动维护的外部账户只能在有足够信息时参与家庭配比：

- 名称包含“股票”“证券”的账户暂按股票 / 权益统计；
- 余额宝、零钱通等现金类账户统计为现金流；
- 且慢、其他平台如果只录入一个总余额，没有底层基金明细，会列为“待确认账户”；
- 待确认金额会显示在家庭资产总览里，但不会被算法伪装成精确的股票、债券或黄金，也不会直接改变某只基金的买卖金额。

当你把外部平台的基金拆成投资方向和基金记录后，系统才能使用同样的官方分类、净值和目标仓位规则进行计算。这样“某证券账户”和“某且慢账户”在家庭层面都能被看见，但只有拥有底层数据的一层会产生基金级发车信号。

### 16.5 这套算法和年化 5% 的关系

年化 5% 是长期目标，不是每日必须完成的指标。系统用它来约束风险和资产分配，不会把年度缺口直接转换成追涨指令。

真正执行时，优先级是：

```text
先保留现金流和安全垫
→ 按投资方向目标分配长期资产
→ 目标缺口分批补仓
→ 高风险趋势破坏时分批降仓
→ 每月复核家庭资产配比和数据重复
```

每日信号只使用 T-1 正式净值，金额是按订单本金估算的“建议上限”，不是必须成交的订单，也没有提前扣除平台最终费率。你仍需在支付宝、且慢或证券账户确认限购、费率、到账时间和实际可用余额。

## 十七、当前信号的已知边界

系统现在能做的是目标缺口、趋势过滤、回撤恢复、分批金额、组合集中度和家庭账户数据质量。它还不知道每个外部平台的实时底层持仓、交易滑点、税费、基金经理变化和未来宏观环境，因此不能保证 5% 目标，也不会自动替你下单。

### 17.1 且慢的“长赢”不是一只基金

且慢里的主理人组合更像一个“模型组合账户”：主理人会在组合里安排多只基金，并在需要时调仓。账户余额本身只能说明“这笔钱跟随了哪套策略”，不能直接说明其中股票、债券、黄金各占多少。

因此系统现在会保存“跟随策略”字段。录入时可以填写主理人和组合名称。在没有同步组合成分和调仓记录之前，它会显示为“策略账户 / 待细分”，不会擅自把整笔余额算成股票或债券，也不会根据账户总余额生成单只基金的买卖信号。

如果以后能导出且慢的持仓明细，建议按“组合—成分基金—持仓金额—调仓日期”导入。这样才能把家庭资产饼图拆到真实大类，并把主理人的调仓行为和系统自己的 T-1 趋势信号区分开。

## 十八、这次重构的四块地基

### 18.1 市值配置

家庭资产现在要区分三个数字：

```text
成本价：过去一共投了多少钱
当前市值：现在这笔资产值多少钱
现金余额：现在还能拿来投资多少钱
```

例如一类基金过去投入 40,000 元，但跌到只值 30,000 元。家庭配置应该按 30,000 元计算，不能因为成本价是 40,000 元就误以为这类资产仍然占 40%。成本价只用于计算盈亏。

### 18.2 家庭资产政策

系统新增家庭层政策，用来记录：

- 长期目标年化（例如 5%）；
- 现金安全垫；
- 股票 / 权益、债券 / 固收、黄金、现金流和其他资产的目标比例；
- 再平衡允许偏离范围。

这不是“今天应该买什么”的按钮，而是家庭资产的护栏。只有先知道家庭允许承担多少风险，后面的基金信号才有意义。

### 18.3 且慢策略账户

且慢主理人组合现在作为策略账户管理。每个策略账户可以绑定一个或多个 `userPropertyId`；同一用户的多个资产标识会分别同步后合并为一个持仓快照，不同用户或不同策略账户仍然彼此隔离。系统会同步基金代码、名称、官方大类、市值、占比和收益。

且慢 Token 按策略账户分别保存：在策略中枢里给不同策略账户各填入自己的 Token。页面只显示“已配置”状态，不回显 Token，也不会把不同账号的 Token 混用。每个账户可以绑定一个或多个资产标识，具体标识由用户在自己的账户中配置。

同步会保留原始接口响应和日期快照。同一日期再次同步时，只替换该日期的快照，不会重复累加；且慢子账户金额也不会覆盖策略账户的合并家庭资产余额。

其中“盈米宝”按两层分类处理：官方产品仍记录为货币基金 / 现金管理类，但家庭资产配置归入“现金流”。它会进入家庭资产总账和饼图，用作流动性资金池，但不会生成普通基金的买入、卖出或暂缓信号。已同步底层持仓的且慢账户使用底层持仓替代账户余额参与配比，避免重复计算。

### 18.4 回测

回测使用下面的顺序：

```text
第 T-1 天收盘后计算均线
→ 第 T 天的下一净值点执行
→ 扣除买入 / 卖出费率
→ 统计收益、最大回撤、波动率、夏普、换手和交易次数
```

例如系统在 10 月 13 日收盘后发现趋势转强，回测不会使用 10 月 13 日之后才知道的数据，而是在下一个可用净值点执行。这可以避免“看到了结果再假装提前做决定”的问题。

回测只能帮助比较规则，不代表未来收益。特别是刚接入的策略组合，在没有足够历史成分快照之前，只能先做账户和配置分析，不能假装拥有完整的历史回测数据。

## 十九、P0 闭环功能

### 19.1 数据同步状态

系统现在会记录基金净值、基金资料和且慢账户同步的状态、时间、条数和失败原因。策略中枢里的“数据同步状态”可以帮助你判断：今天看到的信号是不是使用了新数据。

且慢定时接口为 `/api/cron/qieman-sync`，部署环境可以把它安排在每月 1 号调用；页面里的“同步且慢”仍然可以作为立即重试入口。数据同步成功不代表资产一定上涨，只代表数据已经写入系统。

### 19.2 发车信号执行记录

今日基金信号现在可以记录：

- 建议买入或卖出的金额；
- 实际执行金额；
- 已执行、部分执行、已跳过或待执行；
- 执行日期和备注。

这不会自动修改交易记录，也不会连接支付宝下单。你在外部平台完成操作后，再回到系统记录实际金额，系统才知道这次信号是否真正执行。

### 19.3 家庭再平衡建议

策略中枢会按家庭当前可识别市值、目标比例和允许偏离范围计算：

```text
目标金额 = 家庭总市值 × 目标比例
缺口金额 = 目标金额 - 当前市值
```

例如家庭总市值为 100,000 元，股票目标比例为 40%，当前股票市值为 32,000 元，那么理论缺口就是 8,000 元。它只是家庭层面的金额参考，不是必须执行的订单；实际仍要先确认现金安全垫和当月可投入现金。

### 19.4 组合级回测

组合回测会把家庭目标大类的比例平均分配给有足够历史净值的基金，每月第一交易日再平衡，并且：

- 只用 T-1 数据做判断；
- 在下一可用净值点执行；
- 扣除买入和卖出费率；
- 保留无法买入时的现金；
- 统计总收益、年化收益、波动率、夏普、最大回撤、换手和交易次数。

当前回测不包含没有历史成分快照的且慢策略账户，也不代表未来一定能达到年化 5%。

### 19.5 回测数据不够时怎么办

回测最怕的是“样本太少，却把偶然结果当成规律”。所以系统会先检查有效净值观察日数量：

```text
少于 126 个观察日       → 数据不足，不计算组合指标
126～755 个观察日       → 可做初步研究，但结论较弱
756～1,259 个观察日     → 推荐用于策略比较
1,260 个及以上观察日    → 数据相对稳健
```

这里的观察日是基金已经保存的有效净值日期，不是自然日数量。126 个交易日大约需要半年，756 个交易日大约对应三年，1,260 个交易日大约对应五年。

如果数据不足，正确做法是：

1. 继续每日同步净值，让样本自然累积；
2. 先使用“今日基金信号”做规则观察，但不要把短样本回测当作收益证明；
3. 可以单独接入经过核验的历史数据源，但不能把未经验证的指数代理、未来数据或手工猜测数据混进正式回测；
4. 等到达到最低样本量后，再比较收益、回撤、波动率和夏普比率。

组合回测页面还会列出被排除的基金以及原因，例如“历史净值不足”“未纳入家庭目标大类”或“目标比例为 0”。这比把没有数据的基金默认为 0% 更诚实。

### 19.6 P0 回测报告怎么看

升级后的回测报告不是只有一个收益数字，而是分成几组检查：

- **基础结果**：总收益、年化收益、波动率、夏普、最大回撤、换手和交易次数；
- **时间切分**：训练区间用于观察规则，验证区间用于检查规则是否换一段时间仍有效，盲测区间用于最后一次不参与调参的检查；
- **费率压力**：把买卖费率分别按 1 倍、2 倍、3 倍计算。如果费率稍微增加，结果就完全失效，说明策略对交易成本过于敏感；
- **再平衡敏感性**：比较每月和每季度再平衡。如果两者差异很大，说明结果依赖调仓频率，实际执行要更谨慎。

例如：

```text
月度再平衡年化：6.2%，最大回撤：18%
季度再平衡年化：5.9%，最大回撤：17%
```

两组结果接近，说明规则对频率不太敏感；如果一个年化 10%、另一个年化 2%，就不能只挑表现好的那组来宣传。

### 19.7 P1 虚拟信号账户怎么用

虚拟信号账户是“假设按系统信号执行”的记录本，不会连接支付宝、且慢或证券账户，也不会修改真实交易记录。

第一次使用时：

1. 打开“策略中枢”；
2. 在“虚拟信号账户”输入用于模拟的初始现金；
3. 点击“初始化起始账户”；
4. 系统会读取已经登记的基金交易记录，生成当前虚拟起始仓位；
5. 以后在首页“今日基金信号”中，对明确的买入 / 卖出信号点击“记入虚拟账户”。

每次记账会保存：信号日期、买入或卖出方向、假设成交净值、金额、份额、手续费和系统给出的原因。

### 19.8 虚拟账户金额怎么算

假设：

```text
买入金额：1,000 元
买入费率：0.15%
假设成交净值：2.00 元
```

则：

```text
手续费 = 1,000 × 0.15% = 1.50 元
买入份额 = 1,000 ÷ 2.00 = 500 份
现金减少 = 1,000 + 1.50 = 1,001.50 元
```

卖出时则扣除卖出手续费，现金增加“卖出金额 - 手续费”。系统会检查买入现金是否足够，也会检查卖出份额是否足够。虚拟账户的价格优先使用信号日期之后的第一个可用净值点，符合 T-1 判断、下一净值点执行的回测口径。

虚拟账户的用途是回答：

```text
如果我长期按照这套规则执行，信号是否持续出现？
买卖金额是否超出家庭现金边界？
卖出后是否真的降低了趋势资产风险？
```

它不能证明未来一定赚钱，也不能替代你在真实平台上的成交确认。

## 二十、当前完整使用流程

可以把系统理解成下面这条链路：

```text
每日同步基金净值和资料
        ↓
系统只用 T-1 数据生成买入 / 卖出候选
        ↓
策略中枢检查家庭目标配置和现金安全垫
        ↓
首页查看信号原因和建议金额
        ↓
在支付宝、且慢或证券平台人工执行
        ↓
回系统记录真实执行金额，或记入虚拟信号账户做规则复盘
        ↓
每月查看家庭配比、再平衡缺口和组合回测
```

这条链路的关键是“系统辅助决策，人来确认执行”。系统不会因为年度目标有缺口，就自动追高、加杠杆或一次性买满。

## 二十一、文档中的数据边界

本文只描述系统能力和脱敏示例，不包含任何真实账户名称、资产编号、Token、基金持仓金额或个人身份信息。页面运行时显示的数据属于当前登录用户，不应复制到公开文档、截图或代码仓库中。
